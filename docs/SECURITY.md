# Безопасность DuckOS

## Безопасные значения по умолчанию

- Команды запускаются как обычный пользователь; автоматического sudo/elevation нет.
- inotify-exec вызывает процесс через список аргументов (shell=False), подставляет только {path} и {event} и не интерпретирует shell-операторы.
- proc-env-dump маскирует переменные, чьи имена похожи на пароль, токен, ключ, credential или secret. Из аргументов процесса маскируются значения после известных secret-флагов.
- dir-tree-diff и disk-hotspots не следуют по symlink-каталогам.
- atomic-write создаёт временный файл рядом с назначением, синхронизирует данные и каталог, затем выполняет атомарную замену.
- mount-audit, oom-score-map, irq-balance-check, entropy-gauge и procfs collectors работают на чтение.
- Submodule исходники не импортируются динамически и не исполняются автоматически.

## Ограничения

Маскирование секретов эвристическое. Не передавайте вывод process dump в публичные логи без проверки. /proc/<pid>/environ может быть недоступен из-за прав, ptrace scope или настроек ядра.

inotify-exec предназначен для доверенных локальных каталогов и команд. Он не является песочницей: запущенная команда получает права пользователя, который запустил DuckOS.

atomic-write заменяет указанный файл. Проверьте путь и содержимое перед запуском; команда не пытается угадать намерение оператора.

DuckOS пока не предоставляет security boundary уровня ОС, sandbox для приложений, secure boot, подпись системных пакетов или управление привилегиями.
