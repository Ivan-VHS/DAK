How the pieces relate / 02

A federation, not a monolith.

Projects stay independently buildable and maintainable. Integration is described through explicit repository pins, contracts and documented interfaces.

One direction. Separate responsibilities.

DuckOS is the ecosystem's operating-system track. Reaper supplies language and policy tooling. The other repositories are focused workbenches with their own runtimes and release boundaries.

The distinction matters: a documented integration point is not the same as a component already running inside the kernel. The portal keeps that line visible.

Engineering approach / 03

Clarity is a feature.

The same standard runs through the project descriptions: state what exists, keep boundaries explicit and make local work predictable.

01 / LOCAL

Local by default

Prefer offline workflows and user-controlled data paths. No hidden cloud dependency is implied by a project card.

02 / BOUNDED

Explicit boundaries

Keep hardware access, privileged actions, runtime adapters and experimental tracks clearly separated.

03 / EVIDENCE

Evidence over hype

A passing contract test proves the tested contract—not a complete kernel, driver, compiler or production system.

04 / HUMAN

Tools for people

Readable interfaces, practical documentation, accessibility and predictable recovery belong in the engineering work.
